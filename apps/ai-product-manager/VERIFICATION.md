# Проверка «Контура задач»

Кейс собран и проверен локально. В сравнении справа открывается это приложение: http://localhost:4406/task-review/.

| Сценарий                           | Прямой путь                 |
| ---------------------------------- | --------------------------- |
| Проверка задач и исходника         | `#/review`                  |
| Новый документ                     | `#/analyze`                 |
| Разбор                             | `#/review/sample-cancelled` |
| Передача в трекер                  | `#/export`                  |
| Исправление сохранённого документа | `#/edit/:jobId`             |

Новый документ и исправление получают UUID редактора в адресе. Черновик восстанавливается по этому адресу. Документы, правки задач, подтверждение пропусков и созданные номера сохраняются через demo-kit.

## Проверки команд

Команды выполнены из корня `portfolio-cases`.

| Команда                                        | Результат                                         |
| ---------------------------------------------- | ------------------------------------------------- |
| `npm run typecheck -w apps/ai-product-manager` | exit 0                                            |
| `npx prettier --check apps/ai-product-manager` | All matched files use Prettier code style!        |
| `node scripts/build.mjs ai-product-manager`    | JS 82.1 KB gzip / budget 150 KB; Built 1 case(s). |
| `npm run scan`                                 | NDA scan: clean, 290 files, 34 denylisted terms   |

До исправления два регрессионных теста воспроизводили потерю нового документа: при одновременном создании в двух вкладках и при выборе документа в устаревшей вкладке. После исправления они проходят.

## Проверки браузера

В свежих контекстах Chromium проверены пять экранов на ширине 375, 768 и 1440 px. Переполнения по горизонтали, ошибок JavaScript и внешних сетевых запросов нет. Размеры доступных элементов управления проверены; небольшой checkbox имеет общую кликабельную подпись. Контраст основных текстовых ролей рабочего экрана составляет от 5.7:1 до 11.66:1.

Две заранее открытые вкладки создали разные документы одновременно. После перезагрузки обе вкладки показывают оба документа. Выбор документа остаётся контекстом вкладки. Правки разных задач объединяются; конфликтующая правка одной задачи отклоняется с сохранением введённого текста в форме.

Проверено сохранение черновика при изменении эпика и добавлении критерия из другой вкладки. Грязная форма блокирует фильтры, навигацию, экспорт и скачивание до сохранения или отмены. Два редактора исправления одного документа сохраняют разные тексты после перезагрузки.

Вставка примера и загрузка файла имеют возврат предыдущего текста. Ошибка UTF-8 сохраняет введённый текст. Документ, содержащий только заголовок, открывается для исправления; повторный разбор сохраняет ID документа. Черновик исправления переживает перезагрузку.

Пустой критерий сохраняется как пропуск. Передача требует согласия, создаёт пять разных номеров и сохраняет завершённое состояние после перезагрузки. Markdown содержит пять задач, отмечает отсутствие критериев и получает имя документа. Передача в Orbit Track работает на локальных данных кейса.

Проверены точная подсветка исходного фрагмента на телефоне, начальный фокус редактора и возврат фокуса после Escape. Мобильная проверка выполнена эмуляцией размера окна в Chromium.

## Независимая проверка

Проверка кода обнаружила три ошибки: бесконечный повтор после отказа записи, размонтирование грязной формы при внешнем изменении группы и общий черновик исправления для двух вкладок. Все три исправлены и перепроверены.

Оценка до и после по одинаковой экспертной шкале: 39/70 и 54/70. Дизайн-критик и заключительный визуальный проверяющий обязательных оставшихся правок не нашли. Эти оценки относятся к предоставленным экранам и не заменяют функциональные проверки выше.
